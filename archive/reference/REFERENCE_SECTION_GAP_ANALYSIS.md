## What we have that the reference does not — keep these

- **Generated from the compliance-approved markdown.** The reference is hand-authored prose. Ours must stay
  generated, so the delivered HTML can never drift from what Agent 2C cleared.
- **Structured data outside the section.** v2.7 proved Shopify's schema validator counts every `@type` key in
  the *file* as a setting and blows the 40-setting cap. The reference ships JSON-LD inside the section — that is
  the one pattern we must not copy.
- **Liquid-safety of the prose** (the section is parsed, so the copy may not contain `{{`/`{%`).

## Compliance divergence — the reference copy would fail our Filter

The reference's own headings are exactly what the Claims Filter v1.1 forbids:

| Reference wording | Rule it breaks |
|---|---|
| "The Best Wipe System for Pilates Studios" | superlative without a test-tied comparison (Never-Say #13) |
| "Best for: Busy Pilates studios…" | same rule, repeated on every product card |
| "equipment-safe cleaning" | `safe` applied to surfaces (Part 6 / Annex A) |
| "plant-based materials" | OK as substrate wording — but never as a "natural" claim (A-008 boundary) |

Conclusion: adopt the reference's **engineering**, never its **copy**. The generator therefore runs the
prohibited-claim lint over its own output and refuses to declare the artifact clean when it finds one.

## Decision

Rebuild `build_shopify_paste.py` as a **reference-grade section emitter**:
config-driven, settings-editable, media-aware, instance-safe, `data-cro` instrumented, accessible, and gated by
a claims lint + Liquid-safety + schema-limit + FAQ-integrity validation pass.
